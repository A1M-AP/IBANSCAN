# Local release verification — 23 September 2026

The production standalone application builds successfully, with language-aware server rendering, 89 country formats, seven guides, authenticated API routes and optional Google Gemini / compatible AI integration.

## Completed verification

- TypeScript and ESLint pass.
- 323 unit, engine, CSV, BIC, bank-data, localization, API and security tests pass.
- 25 Chromium browser scenarios pass against the production server (24 passed in the final full run; the remaining scenario passed on targeted rerun after correcting an assertion to allow the decorative country flag).
- All 89 SWIFT reference examples validate; invalid checksums, malformed inputs, noncanonical check digits, country lengths and structure errors are tested.
- Real browser flows cover scanning, examples, invalid input, reset, sharing, AI consent and service unavailability, formatting, BBAN calculation, local CSV upload and CSV export.
- Scanner layouts pass overflow checks at 375, 390, 768 and 1440 pixels. Both color themes and tested main flows pass automated WCAG A/AA axe checks. These automated checks do not constitute a full human accessibility certification.
- Server-rendered content remains visible without JavaScript; the scanner cannot serialize an IBAN in a native form submission before hydration.
- Country pages, guides, canonical metadata, sitemap, robots and security headers are verified.
- The Windows launcher starts and reuses its own background preview, rejects unauthorized/cross-origin shutdown, stops it, and restarts successfully. It binds to loopback and does not kill unrelated processes.

## Multilingual and visual release

- English, Italian, German, Spanish and French selection persists across navigation/reload. Core interface, validation errors, tool catalog, country pages and all seven guide editions are localized. Legal draft bodies and the detailed developer reference are explicitly marked English.
- All five languages fit 375, 768, 1092 and 1440 pixel widths. Gray/black light and dark themes pass the automated contrast checks; reduced-motion preferences are respected.
- Bank profiles display sourced names, contact links, available public telephone numbers and accurately labeled headquarters/registered-office addresses.
- Google Gemini request construction, privacy redaction, locale handling, missing configuration, blocked/truncated responses and invented facts are covered by mocked provider tests. No live provider credentials are configured.
- Local Lighthouse mobile audit: performance 96, accessibility 100, best practices 100, SEO 100; FCP 1.0s, LCP 2.4s, TBT 160ms, CLS 0. These are synthetic local measurements, not field guarantees.
- Localized HTML responds with private/no-store cache headers. The AI endpoint without credentials returns a localized 503 and leaves local validation available.

## Deployment boundaries

- No live AI account has been configured or charged. Automated tests exercise actual provider-request construction and grounded response handling using mocked provider responses. Live use requires the environment settings documented in deployment.md.
- The public API uses provisioned hashed bearer keys. The launcher supplies local single-process request protection; public deployments must configure the documented secrets, ingress and distributed limits where applicable.
- The bundled bank directory contains five independently sourced mappings, with separately sourced contacts and headquarters/registered-office details (reviewed 22 September 2026); unsupported matches remain unavailable. Country structure coverage is broader than bank-directory coverage.
- National domestic account checksum algorithms, ownership, balances and account activity are not verified.
- Billing, persistent accounts, team dashboards and administration are deliberately future integration contracts. No fake login, payment, subscription or stored history is presented.
- Advertising and analytics are disabled by default. A provider and appropriate disclosure/consent integration must be configured before enabling them.
- Legal pages are clearly marked deployment drafts. Operator details, actual processors and retention policies must be supplied before public launch.
- Docker and CI configurations are included. The standalone production smoke checks pass locally; Docker itself was not available on this machine and its image build is not claimed as locally verified.

Browser screenshots and test reports are generated under test-results/ and playwright-report/. Performance audit output is generated by scripts/audit-performance.mjs against a running production preview; synthetic local results are not field Core Web Vitals.
